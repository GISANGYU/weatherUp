날씨를 ‘선택하는 무드’로 쓰는 React 라이프스타일 큐레이션 서비스

총 분량 약 6분 · 6개 파트
00 인트로 — 무엇을 만들었나 0:30
대본

안녕하세요. 저희 작품 WeatherUp을 소개하겠습니다. 보통 날씨 앱은 ‘오늘 날씨가 어떻다’를 알려주는 도구죠. 저희는 발상을 뒤집어서, 날씨를 사용자가 직접 고르는 ‘무드(mood)’로 사용했습니다.

맑음·구름·눈·황사·흐림·비·번개 7가지 무드 중 하나를 고르면, 페이지 전체의 색·배경·추천 콘텐츠(패션·음식·액티비티·음악)가 한꺼번에 그 무드로 바뀝니다. 오늘은 이걸 ‘어떻게 구현했는지’ — 상태관리, 스크롤 애니메이션, 핵심 알고리즘, 그리고 첫 페이지 레이아웃 순서로 말씀드리겠습니다.

01 상태 관리 — 한 값이 전부를 결정한다 1:15
대본

가장 중요한 설계는 상태 관리입니다. 외부 상태 라이브러리(Redux 등) 없이 React의 Context API 하나로 끝냈습니다.

WeatherContext가 currentTheme이라는 단 하나의 값을 소유하고, Provider로 앱 전체에 내려줍니다. 그리고 useEffect가 이 값이 바뀔 때마다 <body>의 클래스를 theme-맑음처럼 한 줄로 갈아끼웁니다.

각 컴포넌트는 props로 값을 ‘전달받는’ 게 아니라, 필요한 곳에서 useWeather()로 직접 구독합니다. 그래서 깊은 props 전달이 없습니다. 음악 재생은 별도의 MusicContext가 맡아서, 어느 페이지에서 곡을 눌러도 전역 플레이어가 이어서 재생합니다.

// WeatherContext.jsx — 상태의 소유
const [currentTheme, setTheme] = useState('sunny');

// 값이 바뀌면 body 클래스 한 줄만 교체 → 전체 테마 전환
useEffect(() => {
  document.body.classList.remove(...ALL_THEME_CLASSES);
  document.body.classList.add(`theme-${currentTheme}`);
}, [currentTheme]);
  • 단일 책임 — 화면 전체의 변화 트리거가 currentTheme 하나로 모임 → 디버깅·추적 쉬움
  • 단방향 흐름 — Provider가 소유 → useWeather() 구독 → setter로만 변경
  • 관심사 분리 — 날씨(WeatherContext) / 음악(MusicContext) 두 컨텍스트로 분리
02 스크롤 애니메이션 1:15
대본

스크롤 연출에는 IntersectionObserver를 핵심으로 썼습니다. scroll 이벤트를 매 프레임 듣는 대신, 요소가 화면에 들어오는 순간만 브라우저가 알려주기 때문에 성능에 유리합니다.

useScrollFade 훅은 요소가 보이면 visible 상태를 켜고 바로 관찰을 해제합니다 — 한 번만 페이드인하면 되니까요. About 패널은 이 관찰에 지연(delay)을 단계별로 줘서 위에서부터 차례로 나타나는 ‘스토리텔링’ 효과를 만들었습니다.

헤더는 스크롤이 화면 높이의 70%를 넘으면 7무드 미니 셀렉터 띠가 스르륵 등장하고, 홈의 패션 섹션은 scroll-snap 가로 캐러셀에 오른쪽 mask-image 페이드를 입혀 ‘옆에 더 있다’는 느낌을 줍니다. 모든 모션은 prefers-reduced-motion에서 꺼집니다.

// useScrollFade — 한 번 보이면 관찰 해제(1회성)
const observer = new IntersectionObserver(([entry]) => {
  if (entry.isIntersecting) {
    setIsVisible(true);
    observer.unobserve(el);   // 재관찰 비용 제거
  }
}, { threshold: 0.15 });
  • 왜 IO인가 — scroll 핸들러의 리플로우/과호출 없이 ‘진입 시점’만 콜백
  • CSS가 모션 담당 — JS는 visible 클래스만 토글, 실제 트랜지션은 CSS @keyframes·transition
  • 구름 셀렉터의 둥둥 뜨는 효과 등 장식 모션은 순수 @keyframes + 접근성 대응
03 핵심 스크립트 / 알고리즘 1:30
대본

알고리즘적으로 신경 쓴 곳은 음악 앨범 커버 로딩입니다. 곡 제목으로 iTunes Search API를 호출하는데, 일부 응답이 CORS로 막혀서 JSONP 방식으로 우회했습니다. 받아온 커버 URL은 localStorage에 영속 캐시해서 다음 방문엔 네트워크 요청이 없습니다.

같은 곡을 동시에 여러 카드가 요청하면 낭비니까 in-flight 맵으로 진행 중인 요청을 공유(중복 제거)하고, 앱 시작 시 7테마 전체 커버를 워커 풀(동시 5개 제한)로 미리 받아둡니다. 한꺼번에 수십 개를 던지지 않고 5개씩 흘려보내 브라우저 연결 한도를 안 넘기게요.

로딩 화면은 타이머·커버·이미지 세 가지 Promise를 AND로 묶어, 셋 다 끝나야(그리고 최소 3초) 사라집니다. Daily 페이지는 카테고리 풀에서 나머지 연산(modulo)으로 아침·한낮·저녁 카드를 순환 선택합니다.

// 프리패치 — 워커 풀로 동시 요청 5개로 제한
const CONCURRENCY = 5;
async function worker() {
  while (queue.length) await fetchCover(queue.shift());
}
await Promise.all(Array.from({length: CONCURRENCY}, worker));

// Daily — 풀을 모듈로로 순환, 저작 데이터 있으면 우선
ootd: authored?.ootd ?? pick(pool, i % pool.length);
  • JSONP = CORS 우회 / localStorage = 영속 캐시 / in-flight = 중복 요청 제거
  • 워커 풀 — 동시성 상한으로 네트워크 폭주 방지(생산자-소비자 패턴)
  • 로딩 게이트 — Promise.all 3종 결합 + 최소 표시시간
04 HTML · CSS — 첫 페이지를 이렇게 구성한 이유 1:15
대본

첫 화면(홈)은 위에서부터 ① 풀스크린 히어로 + 무드 셀렉터, 그 아래 ② 4개의 에디토리얼 섹션(패션·음식·액티비티·음악)으로 짰습니다. 잡지 레이아웃처럼 섹션마다 형태를 다르게 줬어요 — 패션은 잘리는 가로 캐러셀, 음식은 3열 그리드, 액티비티는 가운데가 큰 3장 콜라주, 음악은 좌우 분할.

색은 직접 칠하지 않았습니다. 2단계 토큰으로, tokens.css의 원시 색을 themes.css가 --bg·--accent·--text 같은 의미 토큰으로 매핑하고, 컴포넌트는 var(--accent)만 참조합니다. 그래서 <body> 클래스 한 줄만 바뀌면 리렌더 없이 7테마 색이 한 번에 새로 적용됩니다.

패션 섹션은 일부러 오른쪽을 화면 끝까지 full-bleed로 빼고 mask로 흐리게 잘랐는데, 이건 ‘옆으로 넘길 수 있다’는 신호(어포던스)를 주기 위한 의도된 구성입니다.

/* themes.css — 의미 토큰 매핑(2단계 구조) */
.theme-sunny { --accent: var(--sunny-accent); --bg: var(--sunny-bg); }

/* 패션 캐러셀 — 왼쪽은 컨테이너, 오른쪽만 화면 끝까지 + 페이드 */
.styleRow{
  display:flex; overflow-x:auto; scroll-snap-type:x mandatory;
  margin-right: calc(50% - 50vw);
  -webkit-mask-image: linear-gradient(to right,#fff 82%,transparent);
}
왜 이렇게 했나
  • 토큰 + var() → 7테마 전환 비용이 사실상 0 (클래스 한 줄, 재계산 없음)
  • 의미 토큰만 참조 → 컴포넌트는 실제 색을 모름 → 테마 추가·수정이 안전
  • 섹션별 다른 형태 → 단조로움 제거, 잡지 같은 ‘에디토리얼’ 리듬
  • 트립틱 콜라주 = 12칼럼 grid + z-index 겹침 + 세로 중앙정렬로 비대칭 강조
  • 카드 호버 = overflow:hidden + transform: scale(GPU 가속)으로 부드러운 줌
05 마무리 0:15
대본

정리하면, Context 하나가 상태를 쥐고 → CSS 변수가 색을 바꾸고 → IntersectionObserver와 순수 CSS가 움직임을 담당하는 구조입니다. 외부 의존을 최소화하면서도 7개의 무드를 매끄럽게 전환하는 데 집중했습니다. 감사합니다.
