## 🎙 오프닝 · "왜 굳이 React 였나?" (약 50초)

> 발표를 시작하기 전에, 한 가지 질문에 먼저 답을 드리고 싶습니다.
>
> 이 프로젝트, 굳이 React 로 만들 필요가 있었나? 그냥 HTML 과 Vanilla JS 로도 만들 수 있지 않았나? 충분히 나올 수 있는 질문입니다.
>
> 답은 명확합니다 — **WeatherUp 은 본질적으로 React 적인 문제였습니다.**
>
> 핵심은 이겁니다. 사용자가 7개의 날씨 무드 버튼 중 하나를 클릭하면, 그 한 번의 선택으로 Hero, 헤더, 배경 캔버스, 그리고 OOTD · Food · Activity · Music 6개 영역의 콘텐츠가 모두 동시에 갱신되어야 합니다. 바닐라 JS 였다면 영역마다 일일이 DOM 을 잡아서 갱신하는 명령형 코드가 되었을 겁니다. 페이지가 늘어날수록 버그도 함께 늘어나는 구조죠.
>
> React 는 정반대입니다. `currentTheme` 이라는 상태값 하나만 바꾸면, 그 값을 구독하고 있는 모든 컴포넌트가 자동으로 다시 그려집니다. **상태 → UI 의 자동 매핑** — 이게 WeatherUp 의 캐스케이드와 정확히 맞아떨어지는 패러다임이었습니다.
>
> 거기에 7테마 × 6페이지가 동일한 카드 패턴을 다른 데이터로 반복한다는 점, Context API 로 전역 상태를 한곳에 모을 수 있다는 점까지 — 모두 React 가 가장 잘하는 일들이 곧 WeatherUp 의 요구사항이었습니다.
>
> 그래서 이건 'React 를 한번 써본다' 가 아니라, **'React 가 아니면 어색한 문제'** 였습니다. 그 전제 위에서 본격적으로 어떻게 만들었는지 소개드리겠습니다.

## 📄 슬라이드 4 · 네 가지 원칙 (약 50초)

> WeatherUp 을 관통하는 네 가지 원칙입니다.
>
> **첫째, 사용자가 무드를 선택합니다.** 7개의 날씨 버튼 중 한 번의 클릭 — 그 선택이 테마와 콘텐츠를 동시에 결정합니다. 운명이 아니라 의지로 고르는 분위기입니다.
>
> **둘째, 단일 클래스로 전체가 전환됩니다.** `body` 태그에 `theme-X` 라는 클래스 한 줄만 갈아끼우면 색상·분위기·콘텐츠·배경이 일제히 바뀝니다.
>
> **셋째, 셀렉터가 상호작용의 핵심입니다.** 7테마 버튼 row 가 메인 UI 이며, 클릭 한 번에 히어로·헤더·배경·콘텐츠가 모두 동기화됩니다.
>
> **넷째, 4축을 Daily 페이지로 응축합니다.** OOTD · Food · Activity · Music — 네 영역이 따로 흩어진 페이지로만 있는 게 아니라, **Daily 페이지에서 한 무드의 하루로 통째 큐레이션**됩니다. 이게 잠시 후 보여드릴 작품의 정체성 페이지입니다.

---

## 📄 슬라이드 5 · 7테마 시스템 (약 30초)

> WeatherUp 의 시각 시스템은 7가지 날씨 테마로 구성됩니다.
>
> 밝은 계열 4종 — sunny, partly-cloudy, snowy, dusty. 무드 계열 3종 — cloudy, rainy, stormy.
>
> 각 테마는 고유한 배경색과 강조색을 가지고, 그 자체로 분위기를 정의합니다. 예를 들어 sunny 는 밝은 sky 톤에 노란 햇살 강조색, rainy 는 깊은 navy 배경에 비 온 뒤 푸른 강조색입니다.
>
> 별도의 다크모드 토글 없이 **고른 날씨 자체가 밝기를 결정**하는 구조입니다.

## 📄 슬라이드 6 · 테마 토큰 매핑 (약 40초)

> 이 7테마를 어떻게 코드로 관리하는지 보여드리는 슬라이드입니다.
>
> **왼쪽은 원시 토큰**. 각 테마의 실제 색상값을 한곳에 모아둡니다 — `--sunny-bg`, `--rainy-accent` 같은 식으로 7테마 × 6변수가 정의되어 있습니다.
>
> **오른쪽은 그 결과**입니다. 같은 마크업의 카드가 `theme-sunny`, `theme-rainy`, `theme-snowy`, `theme-cloudy` 각각의 클래스가 적용됐을 때 어떻게 보이는지를 그대로 옮겨왔습니다. 코드는 단 한 줄도 다르지 않고, `body` 의 클래스만 바뀝니다.
>
> 이 구조 덕분에 새로운 테마를 추가하거나 색을 바꿀 때 **컴포넌트 코드를 건드릴 필요가 없습니다.**

## 📄 슬라이드 7 · WeatherContext · 단 두 줄 (약 40초)

> WeatherUp 의 전역 상태는 단 하나, **WeatherContext** 가 보유합니다.
>
> 그리고 그 안에 든 건 두 줄이 전부입니다. `currentTheme` — 사용자가 고른 7테마 ID. `setTheme` — 그 값을 바꾸는 액션. **그게 전부**입니다.
>
> 처음에는 forecast 배열, selectedDay, location, loading, error 같은 복잡한 필드들을 두려고 했습니다. 하지만 그건 외부 API 에 매달려야 가능한 모델이었습니다. **외부 데이터를 비우고 사용자 의지만 남기자**, 상태는 단 두 줄로 압축됐습니다.
>
> 이 Context 를 7개 페이지가 `useWeather()` 라는 훅으로 직접 구독합니다. `currentTheme` 한 값이 갱신되는 순간, 그 값에 의존하는 모든 페이지가 일제히 동기화됩니다. **상태의 단순함이 곧 캐스케이드의 힘**입니다.

---

## 📄 슬라이드 8 · 클릭에서 캐스케이드까지 · 4단계 (약 50초)

> 사용자의 클릭이 화면 전체를 갈아치우는 흐름을 4단계로 보여드립니다.
>
> **STEP 1 — User Click.** 사용자가 7테마 셀렉터 중 한 버튼을 클릭합니다. `onClick → setTheme('rainy')` 한 줄이 호출됩니다.
>
> **STEP 2 — Context Update.** WeatherContext 의 `currentTheme` 상태가 갱신됩니다. React 는 그 상태를 구독하는 모든 컴포넌트를 리렌더 큐에 등록합니다.
>
> **STEP 3 — body.theme-X.** App 의 `useEffect` 가 `document.body` 의 클래스를 단 한 줄 교체합니다. 그 순간 의미 토큰 `var(--bg)`, `var(--accent)` 가 새 테마의 원시 토큰을 가리키기 시작합니다.
>
> **STEP 4 — Cascade Render.** Hero, Header, 배경 캔버스, OOTD, Food, Activity, Music — **한 프레임 안에 모두 새 무드로 전환**됩니다.
>
> 강조하고 싶은 건 이겁니다. **외부 API 도, API 키도, 네트워크 요청도 없습니다.** 오롯이 `currentTheme` 한 값이 화면 전부를 결정합니다.

## 📄 슬라이드 9 · 7테마 셀렉터 (약 40초)

> 이제 사용자가 실제로 만지는 UI 인 **7테마 셀렉터**입니다.
>
> 한 줄에 7개의 무드 버튼이 배치되어 있습니다. 각 버튼은 SVG 날씨 아이콘과 테마 이름만 표시합니다 — 날짜도, 기온도, 시각도 없습니다. **데이터 군더더기를 모두 제거하고 무드 그 자체만** 남겼습니다.
>
> 처음 설계할 때는 API 가 받아온 7일치 예보를 카드로 보여주고 사용자는 고르기만 하는 모델이었습니다. 하지만 그건 **운명을 보여주는 UI** 였습니다. WeatherUp 의 본질은 "오늘 어떤 분위기로 살까" 를 사용자가 직접 선택하는 데 있다고 다시 정의했고, 그래서 카드를 **셀렉터로 바꿨습니다.** 날씨를 받아오는 것이 아니라 고르는 것입니다.
>
> 버튼을 클릭하면 `currentTheme` 이 바뀌고, 그 값을 구독하던 모든 영역이 일제히 전환됩니다. 추가로, 스크롤하면 히어로가 사라지고 헤더에 mini chip row 가 흡수됩니다. 어느 페이지에 있든 다른 무드로 즉시 점프할 수 있도록요.

>
> Hero 의 색감과 강조 색이 바뀌고, 배경 캔버스도 광선 회전에서 빗줄기·번개로 전환됩니다. OOTD 는 반팔과 선글라스에서 트렌치와 우산으로, Food 는 시원한 메뉴에서 따뜻한 메뉴로, Activity 는 한강 피크닉에서 카페·영화관으로, Music 은 밝은 시티팝에서 차분한 Lo-fi 로 — **모든 영역이 한꺼번에 큐레이션**됩니다.
>

## 📄 슬라이드 11 · SVG 아이콘 7종 · CSS 애니메이션 (약 35초)

> 7테마 셀렉터의 각 버튼에 들어가는 7개의 날씨 아이콘은 모두 **SVG 와 CSS 애니메이션으로 직접** 그렸습니다.
>
> sunny 는 광선이 회전하고, partly-cloudy 는 구름이 좌우로 이동합니다. cloudy 는 두 겹의 구름이 서로 다른 속도로 흐르고, rainy 는 빗방울이 시차를 두고 떨어집니다. stormy 는 번개가 짧게 깜빡이고, snowy 는 눈송이가 흩날리며, dusty 는 먼지 베일이 맥동합니다.
>
> 전부 외부 라이브러리 없이 **순수 CSS `@keyframes`** 로 구현했습니다.
> *(여유 있으면)* 호버하시면 실제로 동작하는 모습을 볼 수 있습니다.

## 📄 슬라이드 12 · Daily 페이지 · 캐스케이드의 결정체 (약 50초) ⭐⭐

> **이 슬라이드가 작품의 정체성입니다.** 슬라이드 10 의 CASCADE 가 추상적인 비교표였다면, 이건 그 메커니즘이 실제로 살아 숨쉬는 페이지입니다.
>
> WeatherUp 의 메인 페이지는 **Daily** 라는 이름의 페이지입니다. 사용자가 무드 셀렉터에서 한 버튼을 누르는 순간, 화면에는 **그 무드의 하루가 통째로** 펼쳐집니다.
>
> 위에서 아래로 MORNING · AFTERNOON · EVENING 세 시간대가 줄지어 있고, 각 시간대마다 OOTD · Food · Activity · Music 네 영역의 카드가 자리잡습니다. 합쳐서 **12 장의 카드가 한 화면에**.
>
> 단순히 카드를 나열한 게 아닙니다. 카드마다 **서울의 실제 지역**이 박혀 있습니다. 성수동 어니언의 콜드브루, 한남동 꽁뜨의 로제와 카프레제, 망원 한강공원의 자전거. **위치 API 없이 콘텐츠 자체에 지역성을 박아넣은** 차별화입니다. 한국 사용자의 실제 라이프스타일이 페이지 위에서 살아납니다.
>
> 결정적으로 — 셀렉터에서 sunny → rainy 로 바꾸는 순간, 이 12 카드 **전부가 한 프레임 안에 동시 갱신**됩니다. 망원 자전거가 종묘 미술관으로, 콜드브루가 콩나물국밥으로, 시티팝이 Lo-fi 재즈로. `currentTheme` 한 값이 정말로 화면 전부를 결정한다는 — 오프닝에서 말씀드린 그 메시지의 **결정체**가 바로 이 페이지입니다.

## 📄 슬라이드 13 · 7 페이지 · Daily 를 중심으로 (약 40초)

> 작품은 총 7개의 페이지로 구성됩니다.
>
> 중심에 **Daily** — 방금 보여드린 작품의 정체성 페이지. 한 무드의 하루를 통째로 큐레이션.
>
> **Home** 은 7테마 셀렉터와 무드 카피, 그리고 다섯 영역(OOTD/Food/Activity/Music/Daily) 프리뷰를 한곳에 모은 진입 페이지.
>
> **OOTD · Food · Activity · Music** 네 페이지는 Daily 가 발췌해서 보여준 콘텐츠의 **심화 탐험 페이지**입니다. Daily 가 한 무드의 "하루 일정"이라면, 이 네 페이지는 그 무드의 "카테고리별 전체 풀". 예를 들어 Food 페이지에서는 그 무드에 어울리는 모든 가게 — 성수, 익선, 한남, 광장시장까지 — 를 한꺼번에 둘러볼 수 있습니다.
>
> 마지막으로 **About** 은 프로젝트 소개와 디자인 시스템 데모.
>
> 7개 페이지는 모두 같은 WeatherContext 를 구독하기 때문에, **어디서든 `currentTheme` 이 바뀌면 일곱 페이지가 일제히 반영**됩니다.

- **오프닝 React 답변**은 외워서 가는 게 좋음. 첫 임팩트가 발표 전체 분위기를 결정.
- **슬라이드 7 (Context 단 두 줄)** 에서 "복잡한 모델을 버리고 본질만 남겼다" 는 흐름을 강조.
- 슬라이드 **10 (CASCADE)** 에서 박자 한번 끊고 시각 자료를 보도록 유도 — "여기 보시면..." 류 한 문장.
- 슬라이드 **11 (아이콘)** 은 가능하면 노트북 화면에서 직접 호버 시연 → 정적 PDF 의 한계를 깔끔하게 해결.
- **슬라이드 12 (Daily)** 가 작품의 정체성 슬라이드. 노트북으로 발표하면 실제 페이지를 띄워놓고 셀렉터 클릭해서 12 카드가 동시 갱신되는 라이브 시연이 압도적. 발표 시작 전 미리 띄워두기.
- 슬라이드 **6 (테마 토큰 매핑)** 우측 미리보기 4개를 손가락으로 짚으면서 "같은 마크업, 다른 결과" 강조.
- 시간 부족하면 **5, 11** 정도 압축. 핵심 5개 슬라이드: **3 (관점 전환) · 8 (캐스케이드 흐름) · 10 (CASCADE) · 12 (Daily) · 14 (메시지)**.
